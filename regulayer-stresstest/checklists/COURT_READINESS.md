# Court Readiness Checklist

Version: 1.0.0  
Use: Before any legal proceeding involving Regulayer evidence

---

## Evidence Packaging

### Submission Completeness
- [ ] All relevant decision records included
- [ ] Chain integrity report included
- [ ] Governance evidence included (if applicable)
- [ ] Incident disclosures included (if applicable)

### Manifest Verification
- [ ] manifest.json lists all files
- [ ] All file hashes verified
- [ ] No extra files in package
- [ ] Package integrity confirmed

### Accessibility
- [ ] Evidence readable without Regulayer access
- [ ] Standard formats used (JSON, PDF)
- [ ] No proprietary tools required for viewing

---

## Expert Reproducibility

### Verification Tools
- [ ] Offline verifier source code available
- [ ] Verifier can be audited by opposing expert
- [ ] No hidden dependencies in verifier
- [ ] Deterministic output confirmed

### Algorithm Documentation
- [ ] SHA-256 usage documented
- [ ] Ed25519 usage documented
- [ ] Canonicalization algorithm specified (RFC 8785)
- [ ] All algorithms are public standards

### Independent Reproduction
- [ ] Expert can download tools independently
- [ ] Expert can run verification independently
- [ ] Expert can audit code independently
- [ ] No Regulayer API access required

---

## Testimony Preparation

### Witness Readiness
- [ ] Technical witness identified
- [ ] Witness can explain hash chain simply
- [ ] Witness can demonstrate verification live
- [ ] Witness knows boundary statements

### Cross-Examination Prep
- [ ] qna_judge.txt reviewed
- [ ] qna_opposing_expert.txt reviewed
- [ ] HOSTILE_EXPERT_REVIEW.md reviewed
- [ ] All attack scenarios have responses

### Exhibits
- [ ] Sample verification output prepared
- [ ] Chain diagram prepared
- [ ] Timeline of events prepared
- [ ] Incident timeline (if applicable)

---

## Boundary Statements

### What We Prove
- [ ] Record integrity (hash verification)
- [ ] Chain integrity (linkage verification)
- [ ] Authorship (signature verification)
- [ ] Non-tampering (combined verification)

### What We Don't Prove
- [ ] AI correctness
- [ ] AI fairness
- [ ] Legal compliance
- [ ] Business appropriateness

### Disclaimers
- [ ] All evidence includes disclaimer text
- [ ] Disclaimer is consistent across all documents
- [ ] Counsel has approved disclaimer language

---

## Incident Handling (if applicable)

- [ ] Incident disclosure generated
- [ ] Affected scope documented
- [ ] Unaffected scope documented
- [ ] Trust status for each record available

---

## Final Check

- [ ] All evidence verified within last 7 days
- [ ] Legal team has reviewed all materials
- [ ] Technical witness has rehearsed
- [ ] Opposing expert scenario prepared
