PART 5: THE HUMAN IN THE LOOP (HITL) MASTER MECHANIC (CRITICAL INSTRUCTION)
================================================================================

THIS IS THE MOST COMPLEX IMPLEMENTATION MECHANIC IN THE ENTIRE ECOSYSTEM. READ CAREFULLY.

Regulayer implements "Human-in-the-Loop Governance". 
If a user creates an enterprise policy stating "All Prompt Outputs Containing Medical Advice MUST Trigger Action = `REQUIRE_APPROVAL`", then Regulayer physically suspends the HTTP request in mid-air. It does not return the payload. It holds the payload in a queue so a human Compliance Officer can approve or reject it from the dashboard.

If the human takes more than 30 seconds to approve it, the HTTP protocol will automatically drop the connection (Load Balancer Timeout). To prevent this, Regulayer returns an **HTTP 202 Accepted** to the client application, signifying that the request transitioned into a Governance Pause.

You MUST write application code that handles HTTP 202 arrays and switches to an asynchronous polling routine.

<THE_APP_LOGIC_FLOW>
1. App calls `https://api.regulayer.tech/v1/chat/completions`.
2. Proxy evaluates. Triggers `REQUIRE_APPROVAL`.
3. Proxy immediately returns HTTP 202: `{"status": "pending_review", "governance_ticket_id": "gov_a82nd81"}`
4. Your code catches the 202.
5. Your code loops `GET https://api.regulayer.tech/v1/governance/status/gov_a82nd81` every 5 seconds.
6. The JSON returns `{"status": "pending_review"}`.
7. [HUMAN CLICKS APPROVE IN DASHBOARD 1 MINUTE LATER]
8. The polling JSON returns `{"status": "resolved_compliant", "payload": { <the_original_llm_response> }}`
9. Your code extracts the payload and resumes operations.

import httpx
import os
import asyncio
import time

async def robust_regulated_inference(prompt: str):
    headers = {
        "Authorization": f"Bearer {os.environ['OPENAI_API_KEY']}",
        "X-Regulayer-Api-Key": os.environ['REGULAYER_PROJECT_KEY'],
        "Content-Type": "application/json"
    }

    async with httpx.AsyncClient(timeout=35.0) as client:
        response = await client.post("https://api.regulayer.tech/v1/chat/completions", headers=headers, json=payload)
        
        # Scenario 1: Clean and Legal.
        if response.status_code == 200:
            return response.json()
            
        # Scenario 2: Explicitly Blocked (Action = BLOCK)
        elif response.status_code == 403:
            raise Exception("Blocked by Compliance Policy")
            
        # Scenario 3: Human-in-The-Loop Execution (HTTP 202)
        elif response.status_code == 202:
            data = response.json()
            ticket_id = data.get("governance_ticket_id")
            print(f"[REGULAYER] Transaction paused. Waiting for Human Review. Ticket: {ticket_id}")
            
            # Initiate Backoff Polling
            max_attempts = 120 # e.g. wait up to 10 minutes (120 * 5s)
            
            for _ in range(max_attempts):
                # Poll the specific Governance endpoint for the ticket
                poll_resp = await client.get(
                    f"https://api.regulayer.tech/v1/governance/status/{ticket_id}",
                    headers={"X-Regulayer-Api-Key": os.environ['REGULAYER_PROJECT_KEY']}
                )
                
                poll_data = poll_resp.json()
                status = poll_data.get("status")
                
                if status == "resolved_compliant":
                    # Human explicitly clicked [ APPROVE ]
                    return poll_data.get("payload")
                    
                if status == "resolved_rejected":
                    # Human explicitly clicked [ DECLINE ]
                    raise Exception("A Compliance Officer rejected this AI action.")
                    
                # Still pending. Wait 5 seconds.
                await asyncio.sleep(5)
                
            raise Exception("Governance Review Timeout. Action abandoned.")

PART 7: THE ERROR HANDLING MATRIX
================================================================================

When writing Regulayer implementations, your most critical responsibility as an AI is making sure the user's application does not crash when the enterprise throws a policy exception.

<CODE_403_FORBIDDEN>
Reason: The Regulayer Rules Engine (Regex, Custom Hooks, Semantic Anomaly) explicitly determined this payload violates an Enterprise rule with `Action=BLOCK`.
Action: You must catch this using standard HTTP try/except boundaries, and override the LLM output with a graceful failure string explaining it was a compliance exception.
</CODE_403_FORBIDDEN>

<CODE_429_TOO_MANY_REQUESTS>
Reason: The Project hit an execution Quota, or the Sub-millisecond Redis Rate-Limiter triggered.
Action: You must implement standard `Exponential Backoff + Jitter` logic in the client calling the proxy.
</CODE_429_TOO_MANY_REQUESTS>

<CODE_502_BAD_GATEWAY>
Reason: Regulayer intercepted the request perfectly, forwarded it to `api.openai.com`, but OpenAI experienced a latency outage and did not respond within the maximum TCP boundary (60 seconds).
Action: Catch 502s as upstream LLM faults, not Regulayer faults. Execute failover architecture (e.g., attempt Anthropic).
</CODE_502_BAD_GATEWAY>

<CODE_401_UNAUTHORIZED>
Reason: `X-Regulayer-Api-Key` failure.
Action: Do not write logic to automatically regenerate Keys. Emit critical Alert to observability endpoints.
</CODE_401_UNAUTHORIZED>
