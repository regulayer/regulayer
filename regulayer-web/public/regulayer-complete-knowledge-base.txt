# Regulayer Technical Knowledge Base

## Executive Summary
Regulayer is an Active Network Intercept Gateway and Policy Proxy built for EU AI Act compliance. 

Unlike passive AI observability tools (which only log what an AI model did after the fact), Regulayer sits synchronously in the network path between your enterprise application and the target Large Language Model (e.g., OpenAI, Anthropic). It evaluates every AI prompt and response against your compliance policies in real-time, allowing you to intercept, flag, or block non-compliant AI behavior before it reaches your end-users.

All transactions are cryptographically signed using Ed25519 signatures and stored in a tamper-evident database to fulfill strict enterprise record-keeping and non-repudiation mandates.

---

## Core Capabilities (Currently Implemented)

### 1. Reverse Proxy Interception (The Gateway)
The core of Regulayer is the proxy gateway. Your application stops sending requests directly to `api.openai.com` and instead routes them through `api.regulayer.tech`. The gateway intercepts the payload, evaluates it, and forwards it to the target LLM.

### 2. Policy Evaluation Engine
As payloads transit the proxy, Regulayer runs them against evaluating rules. Currently supported execution actions:
- **PASS**: The payload is compliant and routes normally.
- **FLAG**: The payload is marked as problematic in the logs but is allowed to pass to the user.
- **BLOCK**: The payload is forcefully halted. The application receives an HTTP 403 Forbidden.
- **REQUIRE_APPROVAL**: The payload is suspended in-flight and routed to the Human-in-the-Loop queue.

### 3. Human-in-the-Loop (HITL) Governance Queue
Under the EU AI Act, "Human Oversight" is mandated for high-risk applications. If a payload violates a strict policy (e.g., contains financial advice), Regulayer halts the proxy stream and returns an `HTTP 202 Accepted` to the client app, indicating the request is paused.
The transaction appears in the Regulayer web dashboard under the Governance Queue. A human compliance officer can review the exact LLM prompt and output, and manually click "Approve" or "Reject". The client app polls for the decision and resumes securely.

### 4. Cryptographic Ledger
To mathematically prove to regulators that AI audit logs have not been retroactively altered by engineers, Regulayer signs every proxy transaction with an Ed25519 cryptographic signature and chains them sequentially in a PostgreSQL database.

## How to use Regulayer (Integration)

Integrating Regulayer requires almost zero codebase rewrites. Because Regulayer is a proxy, you simply override the network routing of your existing AI libraries.

### 1. The API Key
You must pass two keys during an API call:
- `Authorization: Bearer <YOUR_UPSTREAM_OPENAI_KEY>` (So OpenAI processes the request)
- `X-Regulayer-Api-Key: <YOUR_REGULAYER_PROJECT_KEY>` (So Regulayer authorizes the interception)

### 2. The Base URL
You must point your LLM SDK's base URL to the proxy endpoint.

**Python Example (OpenAI SDK):**
```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-openai-key...",
    base_url="https://api.regulayer.tech/v1",
    default_headers={"X-Regulayer-Api-Key": "rg_live_..."}
)
# Call the LLM normally!
```

**TypeScript Example (OpenAI SDK):**
```typescript
import OpenAI from 'openai';

const client = new OpenAI({
    apiKey: 'sk-openai-key...',
    baseURL: 'https://api.regulayer.tech/v1',
    defaultHeaders: { 'X-Regulayer-Api-Key': 'rg_live_...' }
});
// Call the LLM normally!
```

## Handling Compliance Blocks in Your Code

When an AI payload hits the proxy, there are three main network outcomes you must handle in your application code:

- **HTTP 200 (Success):** The payload passed compliance and the LLM response is returned natively.
- **HTTP 403 (Forbidden):** A Regulayer policy explicitly blocked the transaction (e.g., PII detected). Your application should catch this HTTP exception and return a safe fallback message to the user.
- **HTTP 202 (Accepted):** The proxy triggered a Human-in-the-Loop pause. Your application must begin asynchronously polling the Regulayer `status` endpoint to see when the compliance officer clicks "Approve", instead of crashing due to a timeout.
