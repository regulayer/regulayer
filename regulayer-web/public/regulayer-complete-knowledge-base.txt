1. EXECUTIVE SUMMARY
================================================================================

Regulayer is an Enterprise AI Governance & Compliance platform. It provides a
transparent proxy gateway that intercepts AI model inferences in real-time,
enforces organizational policies, routes high-risk decisions to human compliance
officers via Human-in-the-Loop (HITL) governance queues, and automatically
generates regulatory documentation including EU AI Act Conformity Assessments
and Fundamental Rights Impact Assessments (FRIA).

KEY VALUE PROPOSITIONS:
- Drop-in proxy for OpenAI, Anthropic, Google, AWS Bedrock, Azure, and more
- Real-time policy enforcement before AI responses reach end users
- Human-in-the-Loop governance workflows for high-risk decisions
- Automated EU AI Act conformity documentation generation
- Cryptographically sealed, tamper-proof audit trails (WORM compliant)
- SOC 2 Type II compliant infrastructure
- Role-Based Access Control (RBAC) with project-level isolation

================================================================================
2. WHAT IS REGULAYER
================================================================================

Regulayer is NOT a monitoring tool. It is NOT an observability platform. It is
an active governance layer that sits in the critical path of your AI inference
pipeline.

WHAT REGULAYER DOES:
1. INTERCEPTS every AI model request/response pair transparently
2. EVALUATES each inference against organizational compliance policies
3. BLOCKS or FLAGS non-compliant outputs in real-time
4. ROUTES flagged decisions to compliance officers for manual review
5. RECORDS every action cryptographically in an immutable audit vault
6. GENERATES board-ready compliance reports automatically

WHAT REGULAYER IS NOT:
- It is NOT a log aggregator (it actively governs, not passively logs)
- It is NOT a model training tool
- It is NOT a prompt engineering platform
- It is NOT a chatbot builder

TARGET USERS:
- Chief Compliance Officers (CCOs)
- AI Risk & Governance teams
- DevOps / MLOps engineers integrating AI into production
- Legal teams preparing for EU AI Act enforcement
- Enterprise architects designing regulated AI systems

SERVICE 2: DECISION RECORDER (Port 8001)
────────────────────────────────────────
The append-only cryptographic vault:
- Receives AI decision payloads (input, output, metadata)
- Computes SHA-256 hash of the canonicalized payload
- Links each hash to the previous record (hash chain)
- Signs with Ed25519 cryptographic signatures
- Stores in WORM-compliant append-only storage
- Indexes by organization, project, model, timestamp

SERVICE 3: GOVERNANCE SERVICE (Port 8002)
─────────────────────────────────────────
Human-in-the-Loop review workflows:
- Maintains review queues for flagged decisions
- Allows compliance officers to approve/reject decisions
- Supports annotations and tagging
- Generates evidence bundles for auditors
- Tracks decision timelines
- Integrates with Slack for real-time notifications

SERVICE 4: POLICY ENGINE (Port 8003)
────────────────────────────────────
Real-time rule evaluation:
- Evaluates decisions against declarative JSON policies
- Supports: keyword matching, numeric thresholds, semantic analysis
- Statistical ML anomaly detection (Z-Score based)
- Actions: ALLOW, FLAG, BLOCK, REQUIRE_APPROVAL
- Can be configured per-project or organization-wide

SERVICE 5: REPORTS SERVICE (Port 8005)
─────────────────────────────────────
Compliance reporting and analytics:
- Chain integrity verification
- Governance review summaries
- Incident reports
- Usage analytics
- SLA compliance metrics

SERVICE 6: API GATEWAY (Port 8100)
──────────────────────────────────
The public-facing entry point:
- TLS termination
- API key validation
- Rate limiting
- Request routing to internal services
- CORS handling

6. DATA FLOW PIPELINE
================================================================================

STEP 1: PROXY INTERCEPTION
Your application makes an AI API call through the Regulayer proxy. The proxy
captures the complete request (model, messages, parameters) and the full
response from the AI provider.

STEP 2: GATEWAY ROUTING
The API Gateway validates your API key, checks rate limits, resolves your
organization and project context, and fans out the payload to the Decision
Recorder and Policy Engine simultaneously.

STEP 3: POLICY EVALUATION
The Policy Engine evaluates the decision against all active policies. Policies
can be scoped to specific projects or applied organization-wide. If a policy
triggers, the decision is flagged with the appropriate action (FLAG, BLOCK, or
REQUIRE_APPROVAL).

STEP 4: CRYPTOGRAPHIC SEALING
The Decision Recorder canonicalizes the payload, computes a SHA-256 hash,
cryptographically links it to the previous record's hash (forming an immutable
chain), and signs the entire block with an Ed25519 private key.

STEP 5: GOVERNANCE DISPATCH
If any policy triggered a REQUIRE_APPROVAL or BLOCK action, the decision is
routed to the Governance Service. A review item is created in the HITL queue,
and (if configured) a Slack notification is dispatched to the appropriate
governance channel.

STEP 6: CONFORMITY DOCUMENTATION
All governance actions, human reviews, policy evaluations, and decision
metadata are continuously compiled into structured data that can be exported
as Conformity Assessments and FRIA reports.

8. SDK INTEGRATION (PYTHON)
================================================================================

INSTALLATION:
  pip install regulayer

INITIALIZATION:
  import os
  from regulayer import Regulayer

  # Option 1: Auto-detect from environment
  client = Regulayer()  # Reads REGULAYER_API_KEY

  # Option 2: Explicit configuration
  client = Regulayer(
      api_key="rl_live_your_key_here",
      base_url="https://api.regulayer.tech"  # Optional, defaults to production
  )

BASIC USAGE — @trace() DECORATOR:
  import openai

  @client.trace(model="gpt-4", system_name="customer-support-agent")
  def generate_response(user_query: str) -> str:
      response = openai.ChatCompletion.create(
          model="gpt-4",
          messages=[{"role": "user", "content": user_query}]
      )
      return response.choices[0].message.content

  # This call is automatically intercepted, hashed, and recorded
  answer = generate_response("How do I reset my account?")

MANUAL RECORDING:
  decision = client.decisions.record(
      input_data={"role": "user", "content": "Approve loan for $50,000"},
      output_data={"decision": "approved", "amount": 50000},
      model="gpt-4-turbo",
      system_name="loan-approval-agent",
      metadata={
          "customer_id": "C-12345",
          "risk_score": 0.23,
          "region": "EU"
      },
      tags=["financial", "high-value", "eu-customer"]
  )

  print(f"Decision ID: {decision.id}")
  print(f"SHA-256 Hash: {decision.hash}")
  print(f"Signature: {decision.signature}")

PROXY MODE (RECOMMENDED FOR PRODUCTION):
Instead of using the SDK decorator, you can configure Regulayer as a
transparent proxy in front of your AI provider:

  import openai

  # Point your OpenAI client at the Regulayer proxy
  openai.api_base = "https://proxy.regulayer.tech/v1"
  openai.api_key = "your-openai-key"

  # Add Regulayer auth as a header
  response = openai.ChatCompletion.create(
      model="gpt-4",
      messages=[{"role": "user", "content": "Hello"}],
      headers={"X-Regulayer-Key": "rl_live_your_key_here"}
  )
  # The proxy transparently intercepts, evaluates policies, and records.

11. HUMAN-IN-THE-LOOP (HITL) GOVERNANCE
================================================================================

PURPOSE:
HITL governance ensures that high-risk AI decisions receive human oversight
before impacting end users. This satisfies EU AI Act Article 14 requirements
for human oversight in high-risk AI systems.

HOW IT WORKS:

1. TRIGGER: A policy rule evaluates an AI decision and determines it requires
   human review (action: "require_approval" or "flag")

2. QUEUE: The decision enters the governance review queue visible in the
   dashboard under "Governance"

3. REVIEW: A designated compliance officer opens the decision and sees:
   - The complete AI input (prompt/query)
   - The complete AI output (response)
   - The policy that triggered the flag
   - Risk scores and metadata
   - Historical context

4. ACTION: The reviewer can:
   a. APPROVE — The decision is marked as approved. The justification is
      recorded in the immutable audit trail.
   b. REJECT — The decision is marked as rejected. A rejection message is
      sent (custom message if provided, otherwise default project-level
      decline message). The justification is recorded.
   c. ANNOTATE — Add notes for other reviewers or auditors.
   d. TAG — Categorize the decision for reporting purposes.
   e. ESCALATE — Flag for senior review.

5. AUDIT TRAIL: Every action (approve, reject, annotate) is cryptographically
   recorded with the reviewer's identity, timestamp, and justification.

SLACK INTEGRATION:
When a decision requires review, Regulayer can dispatch a rich notification to
a configured Slack channel. The notification includes:
- Decision summary
- Triggering policy name
- Direct link to the governance dashboard
- Quick-action buttons (on Enterprise plan)

12. POLICY ENGINE
================================================================================

The Policy Engine evaluates every AI decision against a set of declarative
rules. Policies can be created via the API or the dashboard.

POLICY STRUCTURE:
{
  "name": "PII Detection",
  "description": "Flag any output containing personal data",
  "rules": [
    {
      "field": "output_data.content",
      "operator": "contains",
      "value": "social security",
      "case_sensitive": false
    }
  ],
  "action": "flag",
  "scope": "organization",
  "enabled": true
}

SUPPORTED OPERATORS:
- contains       : String contains substring
- not_contains   : String does not contain substring
- equals         : Exact string match
- regex          : Regular expression match
- gt, gte, lt, lte : Numeric comparisons
- semantic       : AI-powered semantic analysis (uses LLaMA 3)

ACTIONS:
- "allow"            : Decision passes, no action taken
- "flag"             : Decision is flagged for awareness, recorded normally
- "block"            : Decision is blocked from reaching the end user (proxy mode only)
- "require_approval" : Decision enters HITL governance queue for human review

EVALUATION ORDER:
1. All active policies are evaluated in parallel
2. The most restrictive action wins (block > require_approval > flag > allow)
3. Multiple policies can flag the same decision
4. All triggering policies are recorded in the decision metadata

13. COMPLIANCE FRAMEWORK: EU AI ACT
================================================================================

The EU AI Act (Regulation 2024/1689) is the world's first comprehensive AI
regulation. Regulayer maps its capabilities directly to EU AI Act requirements:

ARTICLE 9 — RISK MANAGEMENT SYSTEM
Regulayer Mapping: The Policy Engine + Statistical ML Anomaly Detection
constitutes a continuous risk management system. Every AI decision is evaluated
against risk thresholds, and anomalous behavior triggers automatic alerts.

ARTICLE 10 — DATA AND DATA GOVERNANCE
Regulayer Mapping: The cryptographic vault maintains a complete chain-of-custody
for all data flowing through AI systems. Hash chains prove data integrity.

ARTICLE 11 — TECHNICAL DOCUMENTATION
Regulayer Mapping: The Compliance API (/compliance/tech-docs) provides
structured storage for technical documentation. Organizations can upload or
auto-generate documentation describing their AI systems.

ARTICLE 12 — RECORD-KEEPING
Regulayer Mapping: The WORM-compliant Decision Recorder maintains immutable
records of every AI inference, including inputs, outputs, timestamps, model
versions, and all human override actions.

ARTICLE 13 — TRANSPARENCY AND INFORMATION

17. CRYPTOGRAPHIC VAULT & AUDIT TRAILS
================================================================================

HASH CHAIN STRUCTURE:
Every AI decision is cryptographically sealed into an immutable hash chain:

Record N:
{
  "id": "uuid",
  "sequence_number": 12345,
  "payload_hash": "SHA-256(canonicalized input + output + metadata)",
  "previous_hash": "hash of record N-1",
  "chain_hash": "SHA-256(payload_hash + previous_hash)",
  "signature": "Ed25519(chain_hash, private_key)",
  "timestamp": "ISO 8601",
  "organization_id": "uuid",
  "project_id": "uuid"
}

VERIFICATION:
Any record can be independently verified by:
1. Recomputing the payload hash from the original data
2. Verifying the chain link: H(record_N) = SHA-256(payload_hash + H(record_N-1))
3. Verifying the Ed25519 signature with the public key

WORM COMPLIANCE:
- Records can ONLY be appended, never modified or deleted
- Retention periods are enforced based on plan tier:
  - Free: 7 days
  - Pro: 1 year
  - Enterprise: Unlimited (configurable)
- SEC 17a-4 compliant storage architecture

26. GLOSSARY
================================================================================

AI System: Any system that uses machine learning models to make decisions or
generate outputs.

Conformity Assessment: A documented evaluation proving an AI system meets
applicable regulatory requirements.

Decision: A single AI inference event consisting of an input (prompt/query),
an output (response), and metadata (model, timestamp, etc.).

FRIA: Fundamental Rights Impact Assessment. An evaluation of how an AI system
may impact human rights.

Governance Queue: The list of AI decisions awaiting human review.

Hash Chain: A sequence of cryptographic hashes where each hash includes the
previous hash, forming an immutable chain.

HITL: Human-in-the-Loop. A workflow where humans review and approve AI
decisions before they take effect.

Policy: A set of rules that evaluate AI decisions and determine actions
(allow, flag, block, require_approval).

RBAC: Role-Based Access Control. A system where permissions are assigned to
roles, and roles are assigned to users.

WORM: Write-Once, Read-Many. A storage paradigm where data can only be
written once and never modified or deleted.

27. FAQ
================================================================================

Q: Does Regulayer slow down my AI application?
A: In proxy mode, Regulayer adds < 50ms of latency. In async/SDK mode,
recording happens asynchronously and does not block your application.

Q: Can Regulayer block AI responses in real-time?
A: Yes, in proxy mode. The Policy Engine evaluates the response before it
reaches your application. If a "block" policy triggers, the response is
replaced with a governance-approved fallback message.

Q: What happens if I exceed my decision limit?
A: Decisions are not hard-blocked. You receive notifications and your usage
indicator turns red. Upgrading to a higher plan is recommended.

Q: Can I self-host Regulayer?
A: Yes, on the Enterprise plan. We provide Docker images and Kubernetes
manifests for on-premise deployment.

Q: Is my AI data stored by Regulayer?
A: Yes, the input and output of each decision are stored in the cryptographic
vault. This is necessary for governance reviews and audit trails. Data is
encrypted at rest and retention is based on your plan tier.

Q: Can I use Regulayer with open-source models?
A: Yes. Regulayer works with any model — OpenAI, Anthropic, local Llama,
Mistral, or custom inference servers. The SDK captures the input/output
regardless of the underlying model.

Q: How does Regulayer handle multiple environments?
A: Use separate projects for dev/staging/production. Each project has its own
API keys, policies, and decision records.

Q: Can multiple team members review the same decision?
A: Yes. Multiple reviewers can add annotations, but only one can submit the
final approve/reject action.

Q: How do I export compliance reports?
A: Use the Reports API endpoints or navigate to the dashboard. Reports can
be exported as JSON or PDF (on Pro and Enterprise plans).

Q: What is the difference between "flag" and "require_approval"?
A: "Flag" marks the decision for awareness but allows it to proceed.
"Require_approval" blocks the decision in the governance queue until a
human reviewer approves it.
