[ PART 2: THE CRYPTOGRAPHY DEEP DIVE (THE MOAT) ]
=======================================================================

Observability tools (Helicone, Datadog) record AI actions in a database. If an administrator issues `UPDATE logs SET prompt='changed';`, the database mutates. This is legally void in EU AI Act scenarios. 

Regulayer implements mathematically proven non-repudiation.

<PHASE_1_CANONICALIZATION>
A JSON object is inherently un-hashable due to arbitrary key ordering and spacing. Regulayer forces strict RFC-8785 JSON Canonicalization Scheme (JCS).
Input payload contains:
1. `timestamp_ms` (UTC Time).
2. `project_id` (UUID).
3. `prompt` (Base64 string).
4. `response_payload` (Base64 string).
5. `policy_result` (String: PASS/FLAG/BLOCK).
6. `reviewer_id` (Nullable UUID).

<PHASE_2_CHRONOLOGICAL_CHAINING>
To prove that an event was not retrospectively inserted months later, every event is chained to the immediate past event, functioning identically to a Merkle linked-list (BlockChain), but centralized.
`H(n) = SHA-256( Canonical(Payload_n) || H(n-1) )`
If log entry #50 is altered, the underlying hash changes. This makes the stored `H(n)` for entry #50 invalid. Furthermore, entry #51 expects the old `H(n)`, so the entire chain from #50 to #Infinity mathematically explodes. A regulator can instantly write a script to re-hash the table to verify integrity.

<PHASE_3_ED25519_NON_REPUDIATION>
Hash chains prove immutability, but they do not prove Identity. How do we know Regulayer wrote the log, and not a hacker who compromised the DB and rebuilt the entire hash chain from scratch?
Asymmetric Cryptography:
- Regulayer generates a public/private keypair using Ed25519 (Elliptic Curve).
- The Private Key (`sk`) is locked in a hardware KMS (AWS Key Management Service) and never touches RAM for extended intervals.
- After Regulayer generates `H(n)`, it signs `H(n)` using the Private Key to generate `Signature_n`.
- The `Signature_n` and `Public Key` are provided to the Enterprise.
- An enterprise auditor can use `NaCl` or `libsodium` locally to run `crypto_sign_verify_detached(Signature_n, H(n), Public_Key)`.
- If it returns TRUE, it is mathematically guaranteed that the Regulayer proxy (who uniquely holds the KMS private key) witnessed and sealed that transaction.
This satisfies SEC 17a-4 and EU AI Act Article 12 immediately.

[ PART 4: HUMAN-IN-THE-LOOP (HITL) IMPLEMENTATION ]
=======================================================================

The EU AI Act specifies "Human Oversight" (Article 14). Specifically, automation bias must be mitigated, and humans must be capable of deciding not to act on the AI output.

Regulayer implements "Synchronous Blocking Modes".

<GATE_MODE_MECHANICS>
When Policy encounters a `REQUIRE_APPROVAL` trigger:
1. The gateway halts the request buffer. It does NOT close the TCP connection to the client application immediately (unless timeout bounds are reached).
2. It pushes the full event (Prompt, output, metadata) into `regulayer-governance`.
3. The queue state is marked as `PENDING_REVIEW`.

<THE_CLIENT_EXPERIENCE_IN_GATE_MODE>
- For the end-user waiting for the app to load, the chat simply "spins" (loads).
- In reality, the HTTP request is waiting.
- If the reviewer takes longer than the proxy timeout (e.g., 30 seconds), Regulayer returns an HTTP `202 Accepted` to the client app.
- The `202 Response` includes a polling JSON: `{"status": "pending_review", "governance_ticket_id": "gov_193892"}`.
- The enterprise application developers are expected to catch HTTP 202s and show a UI element like: "Your request is under manual review by our Compliance Team."

<THE_REVIEWER_EXPERIENCE>
- A compliance officer opens the Regulayer Admin Dashboard.
- They see the queue. They preview the exact AI generation.
- They click `[ APPROVE ]`.
- A cryptographic signature representing the Reviewer's API token is generated.
- `status` updates to `RESOLVED_COMPLIANT`.
- The client application (which is polling `/v1/governance/status/gov_193892`) receives the unlocked payload and continues execution.
</GATE_MODE_MECHANICS>

[ PART 8: SYSTEM RESILIENCE AND CIRCUIT BREAKERS ]
=======================================================================

If Regulayer goes down, does the customer's App go down? No.

<FAIL_OPEN_ARCHITECTURE_MECHANICS>
Enterprise architectural guidelines mandate that compliance proxies must not introduce Single Points of Failure (SPOF).
Regulayer implements "Fail-Open" fallbacks.
1. Target Model Timeouts: If `api.openai.com` doesn't respond in 30s, gateway drops connection securely, logging upstream fault.
2. Cryptographic Faults: If `regulayer-recorder` crashes and the hash chain cannot be generated, the proxy STILL routes the traffic to OpenAI to maintain app uptime. It buffers the unhashed logs to Redis temporarily.
3. Total System Catastrophe: If the gateway itself dies, the Application SDK (Python/Node) throws a connection failure. In enterprise codebases, they are trained to catch this and instantiate a secondary fallback client that directly pings OpenAI, stripping the proxy layer to keep their app alive, albeit un-audited.

<RATE_LIMITING>
Implemented via Redis Token Buckets.
If a customer pays for 1,000,000 requests/month, the Control Plane pushes the token allowance. The Gateway consumes tokens via LUA scripts in Redis for sub-millisecond atomic deductions.
If the limit is crossed, the proxy returns `HTTP 429 Too Many Requests`.

[ PART 9: COMMON DEBUGGING / Q&A LOGIC ]
=======================================================================

Q: Why am I getting "401 Unauthorized" when routing through Regulayer?
A: You likely either passed an invalid `X-Regulayer-Api-Key` or failed to pass the vendor key `Authorization: Bearer sk-...` to the target target LLM. The gateway needs BOTH to function (one for Regulayer, one for OpenAI).

Q: Can Regulayer handle streaming responses (Server-Sent Events)?
A: Yes. `regulayer-ingestion-gateway` supports streaming chunks. However, in "Gate Mode" (When policies are set to EVALUATE output), streaming is inherently blocked. You cannot evaluate a full string for PII or semantics if you are returning token-by-token. To gain compliance, the client sacrifices real-time streaming capability.

Q: How much latency does this add?
A: The proxy transiting layer adds roughly 10-25ms. Validating a Regex policy adds <2ms. The majority of AI latency (1500ms+) comes from the LLM provider. Regulayer overhead is mathematically negligible in standard application flows, unless Semantic LLaMA-based policies are used (adding ~200ms).

Q: What happens if an organization deletes a project?
A: The Control Plane soft-deletes the project entity to terminate routing. However, the WORM ledger in `regulayer-recorder` permanently retains the cryptographic decision history. Legal immutability supersedes SaaS deletion requests.

Q: Can I use Regulayer for non-LLM models, like a random forest classification model?
A: You can, via the REST `/v1/decisions` post mode. However, the proxy is optimized specifically for large dynamic byte payloads (text-generation, vision generation).
