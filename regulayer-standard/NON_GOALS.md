## Purpose

This document explicitly defines what this standard does NOT attempt to solve.
Clear non-goals prevent scope creep and misuse of the standard.

---

## Explicit Non-Goals

### 1. Decision Correctness

This standard does NOT:
- Evaluate whether decisions are correct
- Assess decision quality
- Validate decision inputs
- Verify decision outcomes

**Rationale**: The standard records WHAT was decided, not WHETHER it was right.

### 2. Compliance Determination

This standard does NOT:
- Certify compliance with any regulation
- Determine legal adequacy
- Replace legal counsel
- Substitute for regulatory assessment

**Rationale**: Compliance is a legal determination, not a technical one.

### 3. AI Model Validation

This standard does NOT:
- Validate AI model accuracy
- Assess model bias
- Certify model safety
- Evaluate model performance

**Rationale**: Model validation is a separate discipline.

### 4. Consensus Mechanisms

This standard does NOT:
- Define distributed consensus
- Require blockchain
- Specify replication protocols
- Mandate decentralization

**Rationale**: Implementation architecture is outside scope.

### 5. Privacy Preservation

This standard does NOT:
- Anonymize personal data
- Encrypt record contents
- Define data minimization
- Ensure GDPR compliance

**Rationale**: Privacy is application-layer concern.

### 6. Access Control

This standard does NOT:
- Define authentication
- Specify authorization
- Mandate encryption at rest
- Require specific identity systems

**Rationale**: These are implementation concerns.

### 7. Performance Requirements

This standard does NOT:
- Mandate verification speed
- Set throughput requirements
- Specify latency limits
- Define storage efficiency

**Rationale**: Performance is implementation-dependent.

### 8. User Interface

This standard does NOT:
- Define how evidence is displayed
- Specify user workflows
- Mandate visualization approaches
- Prescribe reporting formats

**Rationale**: UI is application-layer concern.

### 9. Network Protocols

This standard does NOT:
- Define wire protocols
- Specify API endpoints
- Mandate transport security
- Prescribe network architecture

**Rationale**: These are implementation concerns.

### 10. Business Logic

This standard does NOT:
- Define when to record
- Specify what to record
- Mandate recording frequency
- Prescribe record content

**Rationale**: Business logic is application-specific.

## Implications

### For Implementers

You are responsible for:
- Access control
- Privacy
- Performance
- User experience
- Compliance assessment

### For Evaluators

This standard enables:
- Evidence integrity verification
- Independent reproduction
- Long-term preservation

This standard does NOT ensure:
- Decision quality
- Regulatory compliance
- System correctness

### For Regulators

This standard provides:
- Verifiable evidence format
- Independent verification capability
- Tamper detection

This standard does NOT provide:
- Compliance certification
- Correctness assurance
- Risk assessment

---

## Anti-Patterns

### ❌ Wrong Usage

"Our AI is correct because it uses this standard."
"We are compliant because we use this standard."
"Our decisions are verified by this standard."

### ✅ Correct Usage

"Our decisions are recorded using this standard."
"Our evidence can be independently verified."
"Our records are tamper-evident."

---

## Conclusion

This standard is deliberately narrow in scope.
It solves the evidence integrity problem.
It does NOT solve every AI governance problem.
